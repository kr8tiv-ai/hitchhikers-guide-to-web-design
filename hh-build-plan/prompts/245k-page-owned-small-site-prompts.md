# 245k - Site prompt generator: one prompt per page or section, small, naming DESIGN.md and its render, with art direction inside (BUG-147)

## Context

Run 11 site-c has 122 generated prompts in `.hitchhiker/prompts/`, averaging about 32 KB each (040.md is 33,407 bytes). Most of each file is the shared context packet (`packages/engine/src/context/packet.ts`, "## Context packet": project, repeated "Attached:" lines, the whole Site Brief, colour lines, motion constants, audio and 3D notes that do not apply). The skeleton (`generateSkeleton`, `SLICES_BY_PHASE`, `job()` in `packages/engine/src/spec/site-prompts.ts`) cuts the build into structure-only steps ("Build the <section> layout on <page>"), so no prompt owns how a page looks. Elevate prompts (REQ-ELEVATE-TYPE / MOTION / IMAGERY / COPY, around line 1400 of site-prompts.ts, generated as 113-116) run after layout is locked. Bodies are authored from goldens in `packages/knowledge/golden/*.md` via `packages/engine/src/spec/author.ts` (`goldenName`, `pickGolden`, `anchorsFor`, `buildAuthorRequest`).

PrimeTime's prompts (C:\Users\lucid\Desktop\primetime-site\build-plan\prompts, read 001-splash-hero.md, 002-what-we-raise.md and 020-fix-round.md; reference only, do not modify) are about 25 lines: goal ("Build S1 exactly as in reference/01"), must_haves, files, non-goals, verification (screenshot at set widths and compare with the named reference file), commit message.

## Deliverables

1. Page-owned prompts. For each primary page the skeleton emits one page prompt that owns the page's composition, content, imagery and motion (or one prompt per major section when the page has more than about four sections; the threshold is a constant). Structure-only "layout" slices for that page are merged into it. Setup, tokens, shared chrome (header/footer), features, SEO, gates, deploy and handoff prompts stay, so every requirement in `plan-coverage.ts` is still covered: keep the REQ ids, attach the merged ones to the page prompt, and make the coverage check pass.
2. Small context. A page prompt body carries at most about 2 KB of design context (constant `PAGE_PROMPT_CONTEXT_BYTES = 2048`, measured on the context block, not the whole file): the page's goal and sections from sitemap/wireframe, the exact copy source, and pointers: "Design source of truth: DESIGN.md (Brand idea, type, tokens, motion, signature effect, image direction)" and "Match: reference/renders/<page>.png". It does not paste the Site Brief, colour lines, motion constant lists, repeated "Attached:" lines, or audio/3D/WebGL notes unless DESIGN.md's signature effect needs them. Add a `site-prompt` packet profile in packet.ts (or a trimmed packet for page prompts) instead of deleting the shared packet other calls use.
3. Format like PrimeTime: front matter as today (id, title, model, effort) plus sections `## goal`, `## must_haves`, `## files`, `## non-goals`, `## verification`, `## commit message`. Verification names the screenshot widths and the render file (245l adds the loop that enforces it).
4. Art direction inside. Remove the separate end-of-queue elevate type/motion/imagery/copy jobs for pages; each page prompt's must_haves carry that page's art direction (from DESIGN.md and `art-direction.ts` `sectionAcceptance` / `directionAcceptance`), type and spacing, motion and imagery upgrade. A single site-wide elevate prompt may remain only for cross-page consistency; say which you kept and why in the commit body. Update `goldenName`, the goldens in `packages/knowledge/golden/` (page.md, section.md, layout.md, elevate-*.md) and `prompt-refresh.ts` to match. Remember the `cli\dist\shipped` copies are generated by the build, not edited by hand.
5. Images: page prompts name owner photos from ASSETS.md first for that page and forbid using the logo file as a card or section image (keep 244f's dedupe rule).
6. Generic, no site-c names. Do not regenerate or edit site-c's queue.

7. Compose, do not invent. Page prompts are fewer and denser (one per page by default; split by section only past the threshold). They tell the session to build each section from the `@hitchhiker/design-system` primitives (245d-245e) using the variant the style-world step ranked first for that section (recorded in `.hitchhiker/design/variants.json` by 245e), customising through slots and tokens. A new layout is allowed only when DESIGN.md's Signature techniques names a signature structure for that section; the prompt then says so explicitly.
8. VISUAL-CONSTITUTION.md (245b) is injected verbatim at the top of every build prompt body (it counts toward the 2 KB budget; 245b keeps it short).
9. Reference stills. Each major section prompt (the hero plus the 3-4 key sections DESIGN.md marks, default: hero and the next three primary-page sections by sitemap order) attaches 1-2 stills: the approved render crop for that section and the closest reference screenshot from `reference/refs` (chosen by the section kind; list them by path in a `## references` block). The prompt requires the session to write a short alignment note (3-5 lines: why the planned build matches the stills and the Brand idea) to `qa/alignment/<promptId>.md` before writing code; close fails if the note is missing or empty.
10. The latest coherence drift report (245q), when present, is listed under must_haves as "Address drift report items N-M" for the pages it names.

11. Skill router. Build each prompt's rules block through the 245j router (`selectSkillPacks` / `planSkillLines` in `packages/engine/src/spec/skills.ts`), so a hero prompt gets hero, type and its motion recipe rules only. No prompt carries the whole knowledge pack.
12. Page prompts are generated only after the 245g design-lab gate has passed; `prepareSiteBuild` queues the design-lab prompt first and the page prompts depend on it.
13. For the hero and 2-3 signature sections, mark the prompt `sampling: k` in front matter so the 245n K-candidate runner picks it up.

# Desk UI research

Decisions for the desk redesign. Each one names the component that implements it. Sources are data. The notes are short on purpose.

## Decisions

- Layout grid. One read column, 40rem, with the phase rail beside it from 1100px. The interview is the first block in `main`. The project bar sits in `[data-project-slot]`, after the interview and before the transcript. Implemented by `shell.ts` and `.hh-columns` / `.hh-read` in `packages/app/src/design/components.css`.
- Type scale. Reuse `--type-display` through `--type-micro`. The question stays `--type-title`. Progress, the project name, and nav labels use `--type-small` or `--type-micro`. Implemented by `.hh-qcard__title`, `.hh-progress`, and `.hh-routes` in `components.css`.
- Spacing scale. Reuse `--space-0` through `--space-10` only. The compact mast uses `--space-2` and `--space-3`. The project bar uses `--space-2` and `--space-3`. Implemented by `.hh-mast--desk` and `.hh-save-line.hh-project`.
- Colour. Reuse the cream, ink, and rust tokens. No new hex outside `tokens.css`. The dialog scrim is `color-mix` of `--color-ink`. The current route uses `--color-accent`. Implemented by existing tokens plus `.hh-dialog` and `.hh-routes a[aria-current="page"]`.
- Button hierarchy. Exactly one `.hh-btn--primary` on the desk (Answer), on each empty plate, on Settings (Save settings), and on Install tools (Back to the interview). Restart, Save project, Resume project, and Open project folder are secondary. A picked settings radio uses `.hh-btn--chosen`, not primary. Implemented by `card.ts`, `project-desk.ts`, `settings.ts` `choice()`, and `renderTools` in `routes.ts`.
- Icon set. The repo has no icon font. Route icons are inline SVG, `aria-hidden="true"`, class `.hh-nav__icon`. Implemented by `navIcon()` in `routes.ts`.
- Tooltip. One shared tip: `data-tip` on the control, `role="tooltip"` on a node inside `main`, `aria-describedby` on the trigger. Hover (80ms, hide 200ms), keyboard focus, and a 450ms touch hold. Escape dismisses in the capture phase and does not move focus. A dialog, the tour, and an active microphone still receive that Escape. The tip does not take clicks. The pointer can rest on it because the hide timer watches the pointer. Reduced motion turns the transition off. Implemented by `packages/app/src/client/tooltip.ts` and `.hh-tip`.
- Wordmark. Don't Panic stays, at `min(100%, 16rem)` on desk pages, and `min(100%, 10rem)` under 719px, so the interview is the large object. Implemented by `.hh-mast.hh-mast--desk .hh-wordmark`.
- Phone layout. Under 719px the route list is one horizontally scrolling row of 44px targets, and the composer is `position: fixed` at the bottom of the viewport, with `--hh-keyboard` from `visualViewport`. The mic stays beside the field. Answer is one row, and Suggest and Skip share the next, so the question stays above the field. The composer cannot grow past the viewport. Implemented by the `max-width: 719px` block in `components.css`. `card.css` keeps the sticky rule the older tests lock.

Gallery still draws one Keep this primary per card, and a printed brand kit still draws one Approve per section. Those are separate decisions on one plate. Motion has no single commit, so it has no primary. Those three are recorded as left open in `ui-audit.md`.

## Sources

- https://www.nngroup.com/articles/visual-hierarchy-ux-definition/ (Kelley Gordon, 2021). Hierarchy is contrast, scale, and grouping. If everything is equal, nothing stands out. Decision: the interview card is the only large rust-ruled plate. Component: `.hh-qcard` inside `.hh-interview`.
- https://www.nngroup.com/articles/prioritize-good-content-bubbles-to-the-top/. Put the primary task first. Decision: the question comes before the transcript and before the project bar. Component: `shell.ts` order, filled by `renderDesk`.
- https://www.nngroup.com/articles/closeness-of-actions-and-objects-gui/. Put the action next to the object it changes. Decision: Restart lives in the interview header, not in a distant menu. Component: `interviewHead()` in `routes.ts`.
- https://www.nngroup.com/videos/managing-visual-complexity/ (Raluca Budiu). Predictable places, hierarchy, and progressive disclosure reduce complexity. Decision: the resume list is a closed disclosure inside the project bar. The open-path field and the sample stay visible because the tour and the resume tests need them, and the bar itself sits under the interview. Component: `.hh-project` / `.hh-save-line` in `project-desk.ts`.
- https://www.nngroup.com/articles/progressive-disclosure/ and https://ixdf.org/literature/book/the-glossary-of-human-computer-interaction/progressive-disclosure. Show the next step, hide the rest until asked. Decision: one question at a time, and the resume list opens on demand. Component: the question card and `details.hh-project__resume`.
- https://www.nngroup.com/articles/ten-usability-heuristics/. Error prevention, user control, and visible status. Decision: Restart opens a confirm dialog, Cancel is focused, and the copy says progress is saved. Component: `[data-restart-dialog]` in `interviewHead()`.
- https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/ and https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/tooltip_role. A tooltip has `role="tooltip"`, the trigger points at it with `aria-describedby`, and Escape dismisses it. The visible name stays on the control. Decision: the shared tooltip. Component: `client/tooltip.ts` and `.hh-tip`.
- https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html (SC 1.4.13). Content on hover or focus must be dismissible, hoverable, and persistent. A `title` attribute does not meet that. Decision: tips are not title-only. The saved-path `title` remains only as the full path, beside a `data-tip`. Component: `client/tooltip.ts` and the status line in `project-desk.ts`.
- https://css-tricks.com/tooltip-best-practices/. A tip adds a description. It does not replace the visible label. Use `aria-describedby` when the control already has a name. Decision: every tipped control keeps its visible label. Component: `client/tooltip.ts`.
- https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html. Targets are at least 44 by 44 CSS pixels. Decision: `.hh-btn` and route links keep `min-height: 44px`. Component: `.hh-btn` and `.hh-routes a` in `components.css`.

THE INTERVIEW

PROMPT 01 · INTERVIEW ME ABOUT THE SITE
You are a senior web designer and art director who has built sites that won Awwwards Site of the Day.
Interview me to plan a website. Read my brand brain first: [paste it or attach it].
Ask me one question at a time. Wait for my answer before the next one. Push back if an answer is vague.
Cover:
1. What the site is for, in one sentence, and the one action a visitor should take.
2. Who the visitor is: a specific person, what they want, what they're afraid of, what device they're
on.
3. The offer: what I sell or give away, and why anyone should care.
4. The pages and sections I think I need (you'll fix this list later).
5. The vibe in three words, and three words it must never feel like.
6. Three to five reference sites I love (Awwwards, Godly, anything) and exactly what I love about each.
7. What I already have: logo, photos, video, copy, fonts, an old site.
8. What must never change (an existing page, a video, legal wording).
9. Motion appetite from 1 to 10: 1 is a calm brochure, 10 is a 3D scroll movie.
10. Hard limits: deadline, budget, hosting, things I legally can't say.
When you have enough, write a one-page Site Brief: goal, visitor, offer, vibe, references and what to
steal from each (the thinking, not the look), what exists, what's protected, motion level, limits. Then
ask me what you got wrong.
F IND YOUR REFERENCES
Go to awwwards.com, open Websites, filter to Sites of the Day, and screenshot three you'd steal from. Write
one line on what you love about each: the scroll, the type, the way the menu opens. Steal the thinking, not the
look. The Aura Homes references were Lando Norris, Igloo Inc, Cozy Lake Cabin, Edelschwarz and The
Floating Forest.
PRO MOVE
Answer out loud with voice typing. You'll say better stuff than you'd type, and you'll stop editing
yourself.

PROMPT 02 · WRITE THE SECTION PLAN
Using the Site Brief, write the section plan for the site.
For each page: the URL, its one job, and its sections in order. For each section: a name, what it says

Rules: the homepage hero gets the most attention. No more than one "wow" effect per section. Every page

STEP 04 · THE TRICK THAT MAKES IT AUTOPILOT
WRITE ALL
THE PROMPTS
04
You don't write the build prompts. You make the AI write all of them, in order, each one complete on its own,
each one starting with the same RULES paragraph. That's what lets a coding agent work for hours without
forgetting your brand or wrecking the part you love.
PROMPT 03 · WRITE ME ALL THE BUILD PROMPTS
Now write the complete build package for Grok Build, the coding agent that will build this site in my
project folder.
Format:
1. Start with one RULES paragraph that every prompt repeats word for word. It must include: the project
type (Astro site, or tell me if something else fits better), my brand name spelled correctly, fonts and
colors with hex codes, my voice rules and banned words, everything that must never be touched, "do not
deploy", "do not delete files, move unused ones to /_archive", motion rules (calm or energetic, respect
prefers-reduced-motion, animate only transform and opacity), and "commit to git when done with a short
message".
2. Then numbered prompts, one job each, in build order: setup and backup, site map and navigation, each
page and section, imagery, then the motion and effects pass, then performance, credits page and QA.
3. Every prompt is one copy-paste block: the full RULES paragraph, then "TASK: [name]", then exact
instructions. Name files, components and routes. Say what "done" looks like and what to report back.
4. Each prompt must work on its own. Never write "as before" or "see above".
5. Anything borrowed (code, models, fonts, textures) must get a credits entry in the same commit.
6. Elevated by default: every prompt aims for an Awwwards Site of the Day result, not a regular
website. Each section gets one bold idea, real copy in my voice and a specific detail nobody else would
think of.
7. Put my NO SLOP RULES inside the RULES paragraph, word for word: [paste the NO SLOP RULES].
Write them all. Don't summarize. Save it as a file I can download.
W HY EVERY PROMPT REPEATS THE RULES
Coding agents have short memories and big enthusiasm. If the rules only live in prompt one, by prompt thirty
it has redesigned your homepage and added a crypto section. Repeat them every time. It costs a paragraph
and saves your site.
RULE
Never let a prompt say "as before" or "see above". If a prompt can't be pasted alone, it isn't finished.

STEP 06 · WHEN SOMETHING BREAKS
ROLL BACK,
DON'T PANIC
Something will break. That's not the workflow failing, that's the workflow. Read the error, paste it into Grok Bot,
paste the fix back. Because every prompt commits, the worst case is you lose one step.
# see your checkpoints
git log /-oneline
# then ask Grok Build, in plain English
Revert the last commit, keep a backup branch called backup-[date].
F ULL AUTOPILOT
If your Grok Bot can see the project directly (a shared repo or folder), tell it to run git log and git diff itself
after every step. Now you're approving, it's checking, Grok Build is building. On Aura Homes that's how 55
prompts went through without the protected splash page moving a pixel.
Keep your hands off the code while the agent works. Two people editing the same file is how you get a
website with two front doors.
RULE
The order that works
• Setup and backup first, always.
• Structure: site map, navigation, then each page and section.
• Imagery: drop in your Grok Imagine visuals.
• Motion: smooth scroll, reveals, scroll video, transitions, 3D, glow.
• Finish: media compression, credits page, QA.
Effects come last. Decorating before the walls are up gets you a very pretty tent.

PROMPT 15 · SCROLL-SCRUBBED VIDEO
[RULES]
TASK: Scroll-scrubbed hero video
Build src/components/ScrollFilm.astro: a section about
[400vh] tall with a sticky full-screen stage. As the visitor scrolls through it, the video /public/
media/[file].mp4 plays forward frame by frame, and backwards when they scroll up, using GSAP
ScrollTrigger with scrub: true. First, re-encode the video for smooth seeking with ffmpeg: H.264,
keyframe every frame (-g 1), no audio (-an), 1920px wide, -movflags +faststart, and keep the original
in /_archive. If seeking still stutters, extract frames to WebP (about 120 to 180 frames) and draw them
to a canvas instead. Overlay three lines of copy that fade in at 20, 50 and 80 percent progress:
"[line 1]", "[line 2]", "[line 3]". Poster image first. Mobile and reduced motion get the poster and
the copy, no scrubbing.
M AKE IT SCRUB LIKE BUTTER
Normal web video is compressed so it only has a full picture every few seconds, which is why scrubbing it
backwards stutters. The prompt fixes that by re-encoding with a keyframe on every frame, and falls back to a
stack of still frames drawn on a canvas if it still isn't smooth. That's how the big launch sites do it.
Use a clip with one slow camera move and roughly 400vh of scroll for 10 seconds of video.
Shorter scroll feels rushed. Longer feels like homework.

[RULES]
TASK: QA pass
Install Playwright as a dev dependency. Write tests/qa.spec.ts that, for every page at 375px, 768px,

PROMPT 26 · TYPOGRAPHY AND SPACING PASS
[RULES]
TASK: Typography and spacing pass on [section or whole site]
Audit and upgrade the type and spacing. Define one type scale (display, h1, h2, h3, body, small,
caption) with real contrast between display and body, using only the brand fonts, and use it
everywhere. Tighten letter spacing on big display type, loosen it on small caps. Set body text at 16 to
18px with a line length of 45 to 75 characters and line height around 1.5. Create one spacing scale and
use it for every gap. Break the identical section rhythm: vary alignment, widths and empty space so
each section has its own shape. Report before and after for each section in one line.
PROMPT 27 · MOTION PASS
[RULES]
TASK: Motion pass on [section or whole site]
Audit every animation. Remove anything that moves just because it can. For what's left, give each one a
job (guide the eye, reveal the story, or give feedback) and say which job in your report. Use one
shared set of eases and durations from src/scripts/motion.ts. Add the one motion moment from the Visual
Direction brief if it's missing. Stagger related elements, never animate everything at once, animate
only transform and opacity, and make sure reduced motion gets a calm, complete version. Report what you
removed, what you kept and what you added.
